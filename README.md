# Справочник Атырауского филиала ТОО «ВЖДО» — версия для GitHub Pages

Репозиторий: https://github.com/nor5atyrau-glitch/vjdoatyrau

Обычные GitHub Pages отдают только статические файлы — своего сервера
там нет. Поэтому сохранение сделано иначе, чем на Netlify: администратор
входит с личным **GitHub Personal Access Token**, и правки сохраняются
прямым коммитом в `data.json` этого репозитория через GitHub REST API —
прямо из браузера, без посредников. GitHub Pages подхватывает изменения
автоматически.

## Структура проекта

```
├── index.html     сам сайт
├── data.json      данные справочника (редактируются через сайт или вручную)
├── .nojekyll      отключает обработку Jekyll (не нужна для этого сайта)
└── README.md      этот файл
```

## Как включить GitHub Pages (один раз)

1. Загрузите все файлы из этой папки в корень репозитория
   `nor5atyrau-glitch/vjdoatyrau` (замените старые файлы новыми).
2. В репозитории откройте **Settings → Pages**.
3. **Source**: `Deploy from a branch`.
4. **Branch**: `main`, папка `/ (root)`. Нажмите **Save**.
5. Через минуту-две сайт будет доступен по адресу вида
   `https://nor5atyrau-glitch.github.io/vjdoatyrau/`
   (точный адрес покажет сама страница Settings → Pages).

## Как создать токен для входа администратора

1. Зайдите на [github.com/settings/tokens?type=beta](https://github.com/settings/tokens?type=beta)
   (это раздел **Fine-grained tokens** — они безопаснее классических,
   так как ограничены одним репозиторием).
2. **Generate new token**.
3. **Repository access** → `Only select repositories` → выберите `vjdoatyrau`.
4. **Permissions → Repository permissions → Contents** → выставьте `Read and write`.
5. Задайте срок действия токена (**Expiration**) — например, 90 дней или год,
   по вашему усмотрению. По истечении срока нужно будет создать новый токен.
6. **Generate token** → скопируйте значение (начинается с `github_pat_…`).
   GitHub покажет его только один раз — сохраните в надёжном месте
   (например, менеджере паролей).

Токен даёт доступ на запись **только к этому одному репозиторию** — не ко
всем вашим репозиториям на GitHub.

## Как пользоваться сайтом

- Обычные посетители просто открывают сайт — доступ на чтение публичный,
  токен не нужен.
- Администратор нажимает **«Вход для администратора»** в шапке сайта и
  вставляет токен из шага выше. Сайт проверит у GitHub, что токен
  действителен и имеет право записи в репозиторий, прежде чем пустить
  в режим редактирования.
- Все правки (сотрудники, подразделения) сохраняются кнопкой в
  соответствующей форме — под капотом это коммит в `data.json` через
  GitHub API. Токен хранится только в памяти вкладки браузера и
  пропадает при закрытии страницы или кнопке «Выйти из режима» —
  каждый раз для входа нужно вставлять его заново.
- Изменения сотрудники видят почти сразу (сайт читает данные напрямую
  с `raw.githubusercontent.com`, а не ждёт пересборки Pages), но полная
  пересборка самой страницы на Pages может занять до 1–2 минут.

## Если что-то пошло не так

В панели администратора есть кнопки **«Скачать data.json»** (сохранить
резервную копию текущих данных на компьютер) и **«Загрузить data.json»**
(подгрузить файл обратно в редактор — полезно, если нужно перенести
данные вручную или восстановить из резервной копии).

Если сохранение через сайт не срабатывает — самая частая причина:
- у токена истёк срок действия — создайте новый по инструкции выше;
- у токена не выставлено право `Contents: Read and write` для этого репозитория;
- токен создан не для того репозитория (`vjdoatyrau`).
